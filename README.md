# CRM + 1С: объединение клиентов без дублей

Сервис забирает все страницы лидов CRM и клиентов 1С, нормализует контакты и объединяет записи в клиентов по графу общих телефонов и e-mail, не склеивая разных людей через служебные (общие) контакты.

**Результат:** `GET /result` → `{"clients": [...], "stats": {...}}`.

## Как работает

1. **Загрузка.** Оба источника читаются постранично строго по `total_pages`, токен передаётся в заголовке `X-Auth-Token`. Сервер на `page > total_pages` снова отдаёт последнюю страницу, поэтому «листать до пустой» нельзя: получились бы дубли.
2. **Нормализация.**
   - Телефон → `+7XXXXXXXXXX`: допускается 11 цифр с 7/8 в начале или 10 цифр, остальное (`123`, `не указан`, `abc`) отбрасывается.
   - E-mail → `trim + lowercase` и проверка формата.
   - Запись без валидного телефона и без валидного e-mail отбрасывается (`records_dropped`).
3. **Служебные контакты.** Контакт считается служебным, если записи с ним — это **3 и более разных клиентов**. «Разные клиенты» считаются как связные компоненты графа *без этого контакта*. Поэтому `ivan@x.ru`, который встречается в трёх записях, служебным не считается: две из них (L1, C1) связаны ещё и общим телефоном, это 2 клиента, а не 3. Поиск повторяется до неподвижной точки: найденный служебный контакт перестаёт склеивать других.
4. **Объединение.** Записи объединяются транзитивно (union-find) по всем не служебным контактам, в том числе по цепочке и между CRM и 1С. Пример: L3 —телефон— C2 —другой телефон— L4.
5. **Объединённый клиент.**
   - `amount` = сумма `amount` (CRM) и `balance` (1С);
   - `name` берётся из записи с самым свежим `updated_at` / `changed`;
   - `phones` и `emails` — все уникальные, без служебных;
   - `sources` — список источников.
6. **Идемпотентность.** Состояния нет: каждый запрос пересчитывает результат с нуля, итог не зависит от порядка записей. Повторный запуск ничего не дублирует.

## Какие контакты служебные и почему

- `+74951234567` — общий телефон: он есть у 4 разных людей («Сотрудник A–D», у каждого свой e-mail). По нему не объединяю и не вывожу его.
- `info@bestcompany.ru` — общий e-mail: он есть у 3 разных людей («Гость 1–3», у каждого свой телефон).

Конфликт имён решается так: имя берётся из записи с самым свежим `updated_at` / `changed`. При равных датах выбор детерминированный.

## Стек и секреты

- Python 3.12, только стандартная библиотека, без зависимостей в рантайме.
- Vercel Serverless Function (`api/result.py`, `vercel.json` переписывает `/result` → `/api/result`).
- Тесты на pytest на сохранённых данных: нормализация, служебные контакты, цепочки, статистика, идемпотентность, пагинация. Тесты прогоняются в GitHub Actions.
- **Токен не хранится в коде.** Он лежит в переменной окружения `OOOBS_TOKEN`: в Vercel это Environment Variables, локально — переменная окружения.

## Запуск локально

```bash
export OOOBS_TOKEN=...            # Windows PowerShell: $env:OOOBS_TOKEN="..."
python -m merge                   # JSON в stdout и в result.json
pip install pytest && pytest      # тесты
```
